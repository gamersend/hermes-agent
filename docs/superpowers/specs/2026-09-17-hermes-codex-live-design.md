# Hermes Desktop GPT-Live Voice Design

## Goal

Add a reversible GPT-Live voice provider to Hermes Desktop using the user's ChatGPT subscription OAuth session, without exposing OAuth credentials to the renderer or changing the existing record/STT/agent/TTS voice path.

## Scope

First release targets Hermes Desktop only. CLI/TUI voice remains unchanged. Existing voice provider behavior remains available and is not migrated.

This feature uses a private, undocumented ChatGPT Codex realtime route. UI and docs must label it as subscription-backed/private and subject to upstream change. It must not request, read, create, or fall back to an OpenAI API key.

## Architecture

The Python Hermes dashboard backend owns the complete upstream control plane:

1. Resolve credentials only from Hermes-owned `~/.hermes/auth.json`.
2. Refresh access tokens before expiry and atomically persist rotated refresh tokens in that store.
3. Create the upstream WebRTC call with the current OMP wire contract.
4. Validate the upstream `Location` header and extract a valid `rtc_*` ID internally.
5. Open and maintain the authenticated sideband WebSocket.
6. Forward only sanitized call state and events to the renderer.
7. Invalidate all call state on teardown.

The renderer owns browser media only:

1. Request microphone access through the existing Electron permission path.
2. Create `RTCPeerConnection`.
3. Create the `oai-events` RTCDataChannel before `createOffer()` so the channel is present in SDP.
4. Send the SDP offer to Hermes with the session/profile context.
5. Apply the backend SDP answer.
6. Attach the remote audio track to an autoplay-enabled audio element.
7. Send local microphone tracks through the peer connection.
8. Ignore data-channel server events once backend sideband is open, except error events.

The renderer never receives or chooses the upstream `rtc_*` call ID. The backend returns an opaque `call_handle`, generated by Hermes, bound to the current session and profile. Every control/event operation requires that handle on the authenticated Hermes path. Teardown invalidates it and rejects reuse.

## Upstream signaling contract

The backend POSTs to:

`https://chatgpt.com/backend-api/codex/realtime/calls?intent=quicksilver&architecture=avas`

Request headers include:

- Define one named wire constant: `CODEX_CLIENT_VERSION = "0.153.0"`, copied from current OMP. Both versioned headers must derive from this constant; Hermes version `0.17.0` is not the wire client version.
- `Authorization: Bearer <Hermes-owned OAuth access token>`
- `OpenAI-Alpha: quicksilver=v2`
- `User-Agent: Codex Desktop/<CODEX_CLIENT_VERSION>`
- OMP originator header with `Codex Desktop`
- `version: <CODEX_CLIENT_VERSION>`
- `x-session-id: <generated realtime session ID>`
- scoped session ID header
- thread ID header
- `ChatGPT-Account-Id` when derivable from the OAuth JWT
- optional OMP attestation only when Hermes can produce it safely; absence is explicit and not replaced by an API key
- `Accept: */*`
- `Content-Type: application/json`

Request body:

```json
{
  "sdp": "<browser SDP offer>",
  "session": {
    "model": "gpt-live-1-codex",
    "instructions": "<live instructions>",
    "audio": { "output": { "voice": "<voice>" } },
    "delegation": { "type": "client" }
  }
}
```

The backend accepts a raw SDP response or `{ "sdp": "..." }`. It rejects empty answers. It extracts `rtc_*` only from the `Location` header and rejects a missing or malformed call ID. The upstream ID remains backend-private.

The sideband URL is derived internally as `wss://api.openai.com/v1/live/<encoded rtc ID>`. Sideband requests use the same OAuth, account, originator, version, scoped-session, thread, and realtime-session headers as signaling. Sideband connection attempts are bounded and exponential; failure is terminal after the configured retry count. Renderer WebSocket connections to OpenAI are prohibited.

## OAuth boundary

The live resolver is separate from `resolve_codex_runtime_credentials()` and `resolve_runtime_provider()`. Those general paths may recover credentials from `~/.codex/auth.json`, which is forbidden here.

The live resolver:

- Reads only the `openai-codex` provider state from Hermes `auth.json`.
- Requires both access and refresh tokens.
- Determines expiry from the access JWT.
- Calls the existing pure refresh operation when near expiry.
- Persists returned access and rotated refresh tokens through Hermes' atomic auth-store writer.
- Never reads `CODEX_HOME`, `~/.codex/auth.json`, credential-pool fallbacks, or another app's state.
- Never returns credentials through REST, WebSocket, Electron IPC, logs, errors, or renderer state.

Codex device-code and token requests use a stable Hermes client User-Agent explicitly. Tests assert that the header is present.

## Backend/renderer API

Add a profile/session-scoped live endpoint family behind the existing Hermes dashboard authentication:

- `POST /api/voice/live/connect`
  - Input: session ID, profile identity, browser SDP offer, requested voice/instructions constrained by server policy.
  - Output: `{ call_handle, sdp_answer, state }`.
  - Never output upstream `rtc_*`, OAuth tokens, sideband URL, or upstream response headers.
- `POST /api/voice/live/control`
  - Input: `call_handle`, allowed control message (`session.context.append`, `delegation.context.append`, or `session.close`).
  - Rejects handles bound to another session/profile or already invalidated.
- `POST /api/voice/live/disconnect`
  - Input: `call_handle`.
  - Idempotently closes sideband/peer state and invalidates handle.
- `WS /api/voice/live/events`
  - Authenticated Hermes WebSocket carrying `call_handle` and session binding.
  - Delivers backend-selected state/transcript/delegation/error events only.
  - Does not expose upstream IDs or credentials.

The browser data channel exists for the upstream media/session contract, but backend sideband is authoritative once open. Data-channel events are ignored except errors. The backend must not forward both event sources or duplicate transcripts/delegations.

## State machine and teardown

States: `idle`, `connecting`, `connected`, `closing`, `closed`, `error`.

Connect failure closes all partially-created resources. Disconnect is safe to repeat and must:

- stop browser tracks via renderer cleanup;
- close backend event/control channels;
- send `session.close` when the sideband is still open;
- close sideband;
- close the upstream call/peer state;
- remove the opaque handle from the active registry;
- clear queued control messages and call-scoped UI state.

A second call must work immediately without relaunching Hermes Desktop. Handle registry entries are bound to profile and session IDs and cannot be transferred.

## Desktop UI

Add Codex Live as one provider option in the existing voice control. Preserve normal voice controls when Codex Live is not selected.

Required states:

- disconnected: explain ChatGPT Codex OAuth/private-route caveat and offer existing Hermes auth flow;
- connecting/auth-refreshing;
- live with mute/end controls and transcript/status;
- retryable failure with safe error text;
- disconnected after teardown.

Hide controls that do not apply to the Codex route, including existing TTS playback settings. Do not show OAuth tokens, upstream call IDs, or sideband URLs.

## Testing

Focused tests defend observable contracts:

1. Live credential resolver reads Hermes auth only and never opens `~/.codex/auth.json`.
2. Near-expiry access token refresh persists a rotated refresh token.
3. Device-code/token HTTP requests include the Hermes client User-Agent explicitly.
4. Signaling request contains exact endpoint, headers, account ID extraction, body, and delegation; `User-Agent` and `version` both derive from the pinned `CODEX_CLIENT_VERSION = "0.153.0"` value.
5. Raw SDP and `{sdp}` answers parse; malformed/missing `rtc_*` Location fails closed.
6. Sideband retries are bounded and use the full authenticated header set.
7. Sideband events are forwarded once; data-channel transcript/delegation events are ignored after sideband opens; data-channel errors still surface.
8. Handles bind to session/profile, reject cross-binding/reuse, and invalidate on teardown.
9. Browser client creates `oai-events` before `createOffer()` and attaches remote audio to an autoplay audio element.
10. A disconnect followed by an immediate second connect succeeds in the state machine.

## Verification gates

- Run focused Python auth/signaling tests.
- Run focused desktop TypeScript/UI tests and typecheck.
- Run the desktop build/typecheck path.
- Exercise the actual desktop voice control with a non-secret mocked upstream only if a live subscription call is unavailable; never claim live OAuth proof from a mock.
- Verify no token, upstream ID, or sideband URL appears in renderer payloads or logs.

## Explicit non-goals

- No CLI/TUI live voice in this change.
- No native OMP Rust/N-API package port.
- No OpenAI API-key fallback.
- No direct renderer-to-OpenAI WebSocket.
- No replacement of existing Hermes voice mode.
- No unrelated provider or auth refactor.
